# F5.5 final physical QA

Status: accepted on 2026-10-03.

The final end-to-end acceptance was performed against the actual production application
at commit `6d7c6f48eb5341f787f0ab1161efea01d4cda22e`. The production frontend used the
accepted S7 artifact, with the existing backend and native arm64 PostgreSQL/PostGIS
runtime. No product defect was found during this stage, so no application code, database
schema, or production data was changed.

## Physical acceptance

Manual user acceptance passed at:

- 1280×800;
- 1440×900;
- 1920×1080.

The accepted flow covered the OpenFreeMap basemap, attribution and map controls, sidebar
expand/collapse and resizing, ordinary and hard refresh, current layer rendering,
min-zoom behavior, automatic and manual loading, persisted settings, district overlays,
search, navigation, ObjectCard, selection, request-state UX, keyboard access, and
console/network sanity. No unresolved critical or high F5.5 regression remained.

The production layer inventory is exactly:

- water;
- park;
- school;
- kindergarten;
- pharmacy;
- hospital;
- clinic;
- road;
- boundary;
- stop.

No S7 proof fixture, General Plan, PZZ, UPI placeholder, temporal layer, raster layer, or
derived-analysis demonstration is exposed in the production UI.

## Search and navigation controls

Search v2 physical and API acceptance included:

- `Юникея` as an ordinary canonical object with normal ObjectCard navigation;
- `Поликлиника №104` as one collapsed logical facility with canonical detail target and
  representative/member-aware highlighting;
- `Невский проспект` as a logical Street with MultiLineString bbox navigation and
  `detail_object_id=null`;
- partial Street search;
- `набережная Обводного канала` retaining Street UUID
  `32aed7f1-0fab-55ba-a173-14dfadeda2e1` across all five intersecting district scopes;
- `проспект королева` matching display name `проспект Королёва`;
- `Гимназия № 642` matching the NBSP-bearing source name;
- Street search remaining available when all ordinary layers are disabled.

A logical Street UUID is never routed to canonical ObjectDetail. Ordinary and facility
results retain their established ObjectCard behavior. Search-origin ObjectCard state is
independent of the current viewport catalog, while map-origin selection follows the
current visible feature scope.

## Loading and settings contract

The accepted S6 contract remains:

- enabled checkbox intent is distinct from zoom-dependent loadability and visibility;
- auto mode issues a bounded, debounced latest-state catalog request;
- manual mode waits through pan, zoom, layer, and district changes until the explicit
  **Загрузить объекты** action;
- one manual action loads the latest bbox, zoom-dependent category set, and district
  scope;
- all ordinary layers off clears catalog features without hiding the selected-district
  overlay or disabling Street search;
- enabled layers below their minimum zoom produce the waiting-for-zoom state rather
  than an empty-result state;
- auto-load and logical layer choices persist across reload;
- **Сбросить настройки** restores the current registry defaults.

Forced backend failure was not introduced in production. Existing regression coverage
remains the acceptance evidence for feature-limit, bbox guard, cancellation, stale
response/error, empty result, and recovery behavior.

## Layer extension contract

S7 acceptance confirms that the current catalog behavior is preserved while the
frontend contract independently represents semantic class, transport, loading strategy,
selection, legend, opacity capability, time awareness, and provenance. Supported
semantic classes are canonical object, reference vector, temporal vector, raster, and
derived analysis. Future proof declarations remain test-only.

Adding another layer that uses an existing source driver requires a registry declaration
and optional source configuration, not a MapView layer-ID special case. Full details are
recorded in [layer-extension-contract.md](layer-extension-contract.md).

## Accepted limitations

The following are intentional roadmap limits, not F5.5 defects:

- the product remains desktop-first at widths of 1280 px and above;
- no mobile layout is implemented yet;
- no official General Plan, PZZ, height-restriction, industrial, or other UPI datasets
  are imported;
- no temporal-layer UI is implemented;
- no StreetCard exists; Street results navigate by bbox;
- no routing or general address-search system is provided;
- opacity capability exists in the layer contract, but no user-facing opacity control is
  implemented;
- no 3D map mode is implemented.

F5.5 is accepted as complete. This closeout does not start UPI or F6.
